# 오비스(OVIS) 워크플로우 관리자 사용 가이드

## 개요
오비스 워크플로우 관리자는 오비스 알파 에이전트의 전체 워크플로우를 CLI 환경에서 직관적으로 실행할 수 있는 통합 도구입니다. 이 도구를 사용하면 데이터 수집부터 콘텐츠 생성까지 모든 과정을 단일 인터페이스에서 관리할 수 있습니다.

## 실행 방법
1. 프로젝트 루트 디렉토리에서 `run-ovis.bat` 파일을 실행합니다.
2. 또는 명령 프롬프트에서 다음 명령을 실행합니다:
   ```
   cd ovis-project
   ovis-workflow.cmd
   ```

## 워크플로우 개요
오비스 알파 에이전트의 워크플로우는 크게 다음과 같은 단계로 구성됩니다:

### 1. 시스템 관리
- Docker 환경 시작/중지
- 로그 확인
- 시스템 상태 모니터링

### 2. 데이터 수집 워크플로우
- 다양한 소스(RSS, 웹 스크래핑, API)에서 뉴스 데이터 수집
- 수집된 데이터 확인 및 관리

### 3. 주제 분석 워크플로우
- 주제 분석 및 클러스터링
- 정치 성향 분석 (좌/우 스코어링)
- MZ 세대 관심도 분석

### 4. 콘텐츠 생성 워크플로우
- 표준 기사 생성
- MZ 세대 타겟 콘텐츠 생성
- 유튜브 스크립트 생성 (짧은/긴/심층 형식)

### 5. 팩트체크 및 검증
- 생성된 콘텐츠 팩트체크
- 콘텐츠 품질 검증

## 주요 기능 사용법

### 데이터 수집
1. 메인 메뉴에서 `5`번 선택 (뉴스 데이터 수집 시작)
2. 수집할 주제와 시간 범위 입력
3. 수집 결과는 `6`번 메뉴에서 확인 가능

### 주제 분석
1. 먼저 데이터 수집이 완료되어야 함
2. 메인 메뉴에서 `7`번 선택 (주제 분석 및 클러스터링)
3. 추가적인 분석이 필요한 경우 `8`번(정치 성향) 또는 `9`번(MZ 관심도) 선택

### 콘텐츠 생성
1. 주제 분석이 완료된 후 실행 가능
2. 메인 메뉴에서 원하는 콘텐츠 유형 선택:
   - `10`: 표준 기사 생성
   - `11`: MZ 세대 타겟 콘텐츠 생성
   - `12`: 유튜브 스크립트 생성
3. 분석된 주제 ID 입력 (주제 분석 결과에서 확인 가능)

### 팩트체크 및 검증
1. 콘텐츠 생성 후 실행 가능
2. 메인 메뉴에서 `13`번(팩트체크) 또는 `14`번(품질 검증) 선택
3. 생성된 콘텐츠 ID 입력

## 유틸리티
- **API 키 설정** (`15`번): Gemini API 키 설정
- **빠른 알파 에이전트 설정** (`16`번): 알파 에이전트 빠른 설정
- **GitHub 백업** (`17`번): 프로젝트를 GitHub에 백업

## 전체 워크플로우 예시

### 뉴스 데이터 수집부터 기사 생성까지
1. 시스템 시작 (`1`번)
2. 뉴스 데이터 수집 (`5`번) - 예: 주제 "정치", 시간 범위 "24"
3. 주제 분석 및 클러스터링 (`7`번)
4. 정치 성향 분석 (`8`번) - 분석할 주제 ID 입력
5. MZ 세대 관심도 분석 (`9`번) - 분석할 주제 ID 입력
6. 표준 기사 생성 (`10`번) - 기사 생성할 주제 ID 입력
7. 생성된 기사 팩트체크 (`13`번) - 팩트체크할 콘텐츠 ID 입력

## 주의사항
- 각 워크플로우 단계는 순차적으로 실행되어야 합니다.
- API 키가 설정되어 있어야 정상적으로 작동합니다 (`15`번 메뉴에서 설정).
- Docker가 설치되어 있어야 하며, 시스템을 시작하기 전에 Docker 서비스가 실행 중이어야 합니다.
- 워크플로우 관리자는 프로젝트 루트 디렉토리에서 실행해야 합니다.
